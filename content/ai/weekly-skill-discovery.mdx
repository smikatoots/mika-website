I like workflows that get better every week.

This is one of my favorites because it is a machine for creating more machines. Instead of manually auditing my own behavior, I run one weekly review that spots repeated work and tells me what to turn into a skill next.

It now hands me two lists, not one. The first is skills to build. The second is edits to the context files Claude reads before every session: preferences I repeated, corrections I made, projects that changed, things I have stopped doing that are still written down. The first list makes Claude more capable. The second makes it know me better. Together they are the difference between a weekly summary and a self-improvement loop.

If you are trying to become more AI-native, this helps a lot. You stop guessing what to automate and start building from real evidence in your day-to-day work.

## Set up the routine

Put this wherever you already look backwards at your week. For me that is Sunday morning. I run mine at 5:00 AM EDT so the report is sitting there before I open anything.

Creating it takes about ten minutes. You name the routine, paste the instructions, pick a model, optionally point it at a repository, and set a trigger that repeats weekly. Give it a boring name you will still recognize in a list six months from now.

![Claude Edit routine modal showing a routine named Weekly skills discovery, an instructions box with the weekly analysis prompt, a Sonnet 4.6 model picker, a repository selector, and a trigger reading Runs every Sunday at 5:00 AM EDT](/ai-guides/weekly-skill-discovery-edit-routine.png "The Edit routine screen: name, instructions, model, repository, and a trigger set to run every Sunday at 5:00 AM EDT.")

Then connect the tools that hold your actual week. The review can only spot patterns in what it can see. Mine reads Gmail, Google Calendar, Google Drive, Granola, Linear, Notion, and Slack, which between them cover almost everything I touch. You do not need all of that on day one. A calendar plus one place you communicate is enough for a real first report, and you can add connectors later without rewriting the prompt.

## The prompt I use

This asks for both outputs: skills to build, and context to update. Swap in your own tools, your own context file names, and your own bar for what is worth automating.

```text
You are running a weekly self-improvement review for me. Your job is to make
yourself more useful to me next week than you were this week.

## Step 1: Read what you already know

Read my global context files (CLAUDE.md and anything it points to, such as
about-me.md, projects.md, voice.md). Note what is already documented so you
do not propose duplicates.

## Step 2: Look at my last 7 days

Review my activity across the tools you are connected to: calendar, email,
Slack, Notion, my task tracker, and my own session history with you. You are
looking for evidence, not vibes.

## Step 3: Find the repeated work

List the tasks I did more than once this week, or that follow the same shape
each time. For each one, return:

* Skill name
* What repeated process it captures
* Where you saw it (specific threads, docs, meetings, or sessions)
* Suggested trigger, inputs, and outputs
* Priority: High (frequent and saves real time), Medium, or Low

## Step 4: Find what you keep not knowing

List things I explained to you this week that should have already been in my
context files. Look for preferences I repeated, corrections I made, new
projects or people, and anything I have stopped doing that is still written
down. For each one, return:

* File and section to change
* Current text (or "nothing")
* Proposed text
* Evidence from the last 7 days
* Confidence: High / Medium / Low
* Whether it is an Add, an Update, or a Remove

## Step 5: Give me a short top of the report

Before everything else, put:

* The top 3 skills I should build first
* The top 3 context updates I should approve first
* Anything you found that contradicts what my context files currently say
* Any question you need me to answer so next week's run is sharper

## Rules

Do not write to any file without my explicit approval. Prefer short,
high-signal additions over long paragraphs. Flag anything uncertain as Low
confidence instead of guessing. Skip one-off tasks unless they are clearly
becoming a pattern.
```

## How I run this each week

1. Block this as a recurring scheduled run.
I run it every Sunday at 5:00 AM so I start Monday with a clean list of what to automate next.

2. Read the report like a code review, not a newsletter.
The routine's job is scanning. Mine is approving. I go line by line: approve what is right, reject what was a one-off, and answer any question it flagged. Skip this and the whole thing becomes another unread digest, which is the most common way these die.

3. Keep the output format strict.
I ask for the same fields every time so I can compare weeks and see what keeps coming back. If the signals show up across multiple tools, it is usually a real pattern worth packaging.

4. Prioritize only the top three of each list.
Best mix of frequency, leverage, and ease wins. Everything else goes into a backlog.

5. Ship one improvement per week, not five.
I pick the single highest-value skill candidate and actually build it. If you have never packaged one before, [the walkthrough for creating a custom skill](/ai/how-to-create-custom-skill) covers the format. Five half-built skills are worth less than one you use every day.

6. Let Claude write the approved context changes.
Once I have approved the Step 4 items, I tell it to write them into the right files. This is where [your second brain](/ai/how-to-give-claude-memory) stops being a folder you made once and starts being something that updates itself with your sign-off. Next week's sessions open already knowing the current version of you.

7. Audit the routine itself once a month.
I look at the last four reports together. If the same skill candidate keeps appearing and I keep not building it, either I build it or I tell the prompt to stop suggesting it. If the reports are vague, the fix is almost always a tighter prompt or a missing connector, not a different model.

> **Key insight:** A repeated workflow is already a draft skill, and a thing you explained twice is already a missing line in your context file. Weekly discovery just makes both obvious.

## What "good" output looks like

A strong weekly report gives you:

- A top 3 shortlist of skills you can act on immediately
- A top 3 shortlist of context updates, each one an Add, an Update, or a Remove
- Clear evidence across Linear, Notion, Slack, Gmail, and your session history
- Trigger suggestions so you know exactly when to use the skill
- Input and output specs so implementation is fast
- A priority rating on skills and a confidence rating on context edits

Removals matter as much as additions. Stale context costs you about what missing context costs you, and it is harder to notice.

If your report reads like a summary of your week, the prompt is too soft. Push it toward proposals with file names and trigger conditions, closer to [the context updater routine](/ai/how-to-keep-claude-md-from-going-stale-context-updater), which asks for exact file-level edits instead of suggestions.
